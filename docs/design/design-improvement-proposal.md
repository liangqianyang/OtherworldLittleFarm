# 《异界小农场》设计完善建议书

> 来源：5 份并行专家评审交叉核对而成（游戏设计主评审 / 关卡地图 / 触屏 UX / 技术可行性 / 平台约束）。
> 评审对象：docs/design/game-design-draft.md、docs/design/first-playable.md、README.md、docs/taptap/publishing.md。
> 说明：所有数值均为评审给出的起点值，最终以灰盒 / 真机实测为准。

---

## 1. 总体判断

- **原则层质量高（约 80 分）**：核心循环、四大体验支柱、失败不清档、限时返场消解篡改动机、平台适配层隔离——5 份评审一致认可，无一项建议推翻。
- **但文档目前是"原则清单"而非"可开发设计"**：缺经济数值、前期曲线、中期里程碑、触屏操作方案、素材来源与包体预算——这些是动工前必须补齐的。
- **产能预警**：§13 MVP 清单对单人开发乐观 30-50%，全量估算 **76-120 人日 ≈ 全职 4-6 个月**；按 6-9 个月留 buffer 规划才可信。技术评审结论：五个受评系统（存档 / 日历离线 / 多波防守 / 装扮吸附 / 钓鱼 QTE）全部技术可行，**瓶颈在内容生产量而非技术**。
- 动工前需先拍板 4 个决策（见 §10）。

## 2. 五份评审共识（可直接执行）

1. **探险高度系统首版降级为"平面 + 遮挡"**（详见 §3.1）
2. **房间可编辑摆放移出 MVP**，改预布置房间展示（§3.2）
3. **NPC 不做任务框架**：JSON 线性对话 + 一次性触发 + flags/affinity 阈值
4. **随机裂隙（§8.2）延后**，同步修改 §8.2 "首版"措辞（对齐 §13，消除 A13 文档不一致）
5. **防守情报系统 = 全文档性价比最高补丁**：怪物口味标签 + 守门人前夜不完全情报（游戏设计与关卡评审独立提出同一方案）
6. **防守禁用数量 / 血量递增式难度**；难度来自波次职责混合 + 波间调整权
7. **存档从第一天带 version 字段 + 滚动备份**，onHide 强制落盘，只存纯数据、绝不序列化节点引用
8. **新手引导做 10 分钟任务链**（种→收→钓→布防；实战首波留给 day4，见 layout-v2-pacing §3.4 拍板 A），不做遮罩教学
9. **空包真机构建提前到实施第 1 步**（原 §14 排第 6 步太晚），立即建立包体基线
10. **真机验收指标**：首包 ≤4MB（预算 ≤3MB）、整包按微信口径 ≤30MB、冷启动 <5s
11. **资源规范**：tile 基准 16/32px、图集合并、pngquant 8-bit、不内置中文字库（系统字体 + 位图字体）、BGM mp3 64-96kbps 放分包
12. **MVP 不启用物理引擎**：防守 / 装扮 / 钓鱼全部网格数学 + 手工 AABB 判定

## 3. 砍掉 / 降级（"三刀"）

### 3.1 刀一：探险高度系统 → 首版"平面 + 遮挡"

- 依据：设计评审判定为最高风险项（高度牵连射线 / 近战可达 / 敌人寻路 / 陷阱效果，若农场也多层等于两套高度逻辑）；技术评审判定为最大单项技术风险（贵在"脚底位置 vs 碰撞 vs 画面高度"的可读性与跨高度判定，不在渲染）。
- 首版替代：平面地图 + y 排序遮挡（角色进入遮挡物后方时遮挡淡出 40-50%）。
- 可选验证：3 天灰盒 spike（y-sort + 楼层 tag）。通过 → 第二张探险图可恢复真实高度；不通过 → 永久降级。**无论 spike 结果，首版都按平面启动。**
- 同步修改：first-playable.md:15 删除"地下通道"；§5.3 措辞改为"首版平面+遮挡，高度玩法见二期"。
- 关卡评审可读性规范中首版仍适用部分：**脚底椭圆软阴影（25-35% 透明度）= 可行走平面唯一真值**（无阴影 = 纯装饰不可交互）；前景遮挡物去饱和压暗 10-15%；镜头整数像素纯平移跟随、角色居中偏下；**不做缩放**。

### 3.2 刀二：房间装扮——可编辑摆放移出 MVP

- 依据：格子摆放 = 拖拽 + 吸附 + 旋转 + 碰撞 + 布局存取，属"编辑器级"系统（约 10-15 人日），却不参与"经营-探险-防守"核心循环验证。
- 首版替代：1 间**预布置房间可参观**（保留温馨家园视觉，供商店页截图）。
- 技术备注（二期采纳）：网格吸附本身低风险（房间=网格 cell，家具存 `{furnitureId, cellX, cellY, rot}`，指针→格子纯数学换算）；真正的坑是**旋转**——像素 90°/270° 通常需美术单独画方向图，二期建议不支持旋转或只做 0/180°。拖拽手感：点选 / 拖动分离（位移阈值约 150px）、幽灵预览上偏 60-80px、支持撤销；验收线=8 件装扮 ≤3 分钟。
- 存档：布局即存档 decor 段，成本极低。

### 3.3 刀三：NPC 任务框架及其他收缩

- NPC 不做任务框架：JSON 线性对话 + 一次性触发。园艺师=种植教学+种子兑换；守门人=预警播报+防守教学。
- 随机裂隙（§8.2）延后：只留预告型入侵（§8.1），避免两条触发链同时调参。
- 品质 / 稀有度延后：数据结构保留 `quality` 字段，MVP 不实装 roll 与分品质 UI；"稀有作物"简化为**贵 + 慢**。
- 图鉴收窄：首版只收作物 + 鱼两类，作为单一数据注册表（见 4.6）。
- 防守波次：2-3 波**固定脚本**（非自由波次系统）；怪物沿预设路径行进，不做 A* / 自由寻路（用 targetPriority 选目标 + 直线转向 + 分离力已够用）；固定 1-2 个出生入口。
- 节气节日：查表框架先行，MVP 只配 2-4 个节气 / 节日验证"周期返场"。
- 天气：只做两条规则——每日 roll 天气 → 鱼池权重变化 + 雨天自动浇水；视觉仅换色调 / 简单粒子。
- 防守作物：MVP 只做减速 + 吸引（圆形光环每帧扫描），阻挡 / 恢复二期。
- §8.3"按突破位置定损"MVP 简化为按漏怪数量定损，归因面板先行（见 4.3）。

## 4. 必补系统（评审发现的最大缺口）

### 4.1 经济闭环【最高优先缺口 A1】

- 现状：全文无货币、无商店、无定价；但 §4.1"购买种子"、§9 旅行商人已被多处依赖——后续每个系统的数值都会卡在这。
- 建议：1 种货币（金币）+ 出货交互 + 价格锚点表（起点值）：
  - 普通作物售价 **8 / 15 / 25**，稀有 **60**；**种子成本 ≈ 售价 35%**。
  - 验收：4+1 作物每种一行——买价、卖价、成熟时长、日收益排序。

### 4.2 新手引导 = 10 分钟任务链【A2】

- §13 现仅"基本新手引导"四字。任务链：种第一块地 → 浇水 → 收获 → 钓第一条鱼 → 首次预兆 → 1 只怪的小防守。
- 验收：无文字教学，仅靠光标指引与 NPC 对话完成首轮闭环；手势即教 ≤60s。

### 4.3 防守情报系统 + 节奏表【性价比最高补丁，A4】

- **怪物口味标签**（每种怪约 3 个：偏好 / 弱点 / 行为，如甜食虫扑高甜作物、飞行种无视地面陷阱）；**守门人**在预告日前 1-2 游戏日给"不完全情报"（类型 / 方向 / 弱点的模糊提示，如"怕火、爱啃庄稼"）。
- 情报不完全 → 布置是下注，不存在万能阵。验收：同一战力下，两份不同情报对应的最优布置不同。
- **节奏**：每 4-6 游戏日一次预告入侵；入侵强度随封印修复度上升。
- **波次编排**（3 波框架，写成配置表）：
  - 第 1 波·探测：单怪种小数量，让玩家看清路径与克制（兼教学）；
  - 波间隔 60-90s：可修补 / 补种 / 有限次挪陷阱——**动态调整权是策略感主体**；
  - 第 2-3 波·组合：按职责混合（护甲顶前排 + 干扰怪偷田），逼玩家分兵；远程怪逼站位。禁止"+20% 数量 / +20% 血量"式难度；
  - 终波·规则变化：裂隙入口偏移或新怪入场。
- **结算**：按位置归因面板（"西侧无覆盖 → 3 株南瓜被吃"），失败即下一轮布置的情报。验收：失败后玩家不看日志能说出哪条路漏了。

### 4.4 存档工程（从第一天）【A9】

- schema：单一版本化 JSON 文档 `{version, ...}` + 迁移函数链（字段只增不删）+ 上一代 `.bak` 备份；只存 id / 坐标 / 数值 / 时间戳，绝不序列化节点引用。
- 落盘时机：结束一天 / 防守结算 / 切场景 / **onHide 强制 flush**；不每帧写。
- 平台约束：微信单 key ≤1MB、总 10MB，官方明确承认系统可能清理。MVP 存档预计 <100KB，单 key 足够；**若超 ~700KB 再分片**（save_meta / save_farm_layout / save_crops / save_inventory / save_collection / save_npc_quest / save_settings）。
- 写失败降级：剔可重建数据 → 只保核心域 → getStorageInfo 查余量并提示。
- 防丢档兜底：设置页一行风险文案（"存档保存在本机，清理 / 卸载会丢失"）+ **「导出存档码」**（JSON 压缩 + base64，复制 / 粘贴恢复）——成本极低，进 MVP。
- 验收：杀进程重开不丢最后一步操作；时间回拨后无负生长、存档不乱。

### 4.5 离线推进（决策点，见 §10.1）【A5】

- **四条红线（无论选哪案都成立）**：① 挂后台 = 暂停（仅冷启动结算离线时长且设上限）；② 防守事件离线**绝不**判定失守，一律顺延到上线后夜晚；③ 时间倒流（`now < lastSaveRealTime`）按 0 处理；④ 规则在游戏内明示。
- 时间实现：整数游戏日计数器 **dayIndex**，在线由"结束一天"显式推进；核心逻辑不直接 `Date.now()`，统一走平台适配层**时间源接口**；作物只存 `plantedDay + wateredDays`，按 dayIndex 差值推算（天然支持离线）。
- 6.2 游戏内日历与真实日期解耦 + 节日周期返场——平台评审明确背书"**务必保留**"（周期返场让日历内容无绝版价值，消解时钟篡改动机）。
- 离线简报卡（图标化）展示离线期间变化。

### 4.6 图鉴 = 数据注册表【A10】

- 图鉴被 6+ 处引用却无定义章节。定为单表数据驱动（id / 分类 / 归属 / 完成奖励 / UI 形态），首版只收作物 + 鱼。避免装扮 / 防守 / 剧情各写一份。

### 4.7 中期里程碑：封印修复度【A3】

- 修复度 0 → 25 → 50 → 100% 各阶段解锁表（作物 / 设施 / NPC / 剧情）——最便宜的进度主轴，撑起 15-40 天中期曲线。

### 4.8 失败情绪层【A8】

- 首败免罚；连败软补偿 = 下次情报更详细（**给情报不削怪**，规避硬核玩家反感动态难度）；修理恢复 = 清单式（修理 + 补种，不建独立任务系统）；战报归因面板本身即教学。

### 4.9 单张探险图重玩性【A7】

- 随机地图生成已延后 → 固定图需要随机要素：采集点刷新表、宝箱位置种子、每日怪物配置变异、伪随机保底。否则第 5 次进图后核心循环的 1/3 失去吸引力。

### 4.10 玩家成长线【A6】

- 明确 2-3 条成长线：工具等级 / 设施等级 / 防守蓝图——否则"准备有意义"（§2.3）没有数值载体。

## 5. 触屏与 UX 方案（回答 §15 第 1 问 / A11）

### 操作布局（设计分辨率 1280×720，横屏）

- **农场：点击移动**（点到交互物 = 交互，空地 = 移动）——单手可完成全部日常。
- **战斗：动态虚拟摇杆**（左半屏任意按下生成原点）+ 攻击钮（直径 ~120px，圆心约 (1150, 560)）+ 闪避钮（96px，圆心约 (980, 470)），距屏幕边缘 ≥24px；近战轻吸附 + 宽无敌帧 + 输入缓冲。
- **热区标准**：≥88 设计 px（≈44-48dp，达 iOS / Android 双标准）；像素小按钮视觉 / 热区分离（视觉最小 64px + 透明 hit 区）。
- **疲劳解法**：工具锁定 + 拖刷（按住划过连续多格）+ 一键收获；中期洒水器。逐格种植 / 浇水 / 收获日点击 72+ 次不可接受。
- **钓鱼**：全屏单点（咬钩窗口 ≥350ms、三重提示、失败零惩罚）；实现用 touchend + `update(dt)` 时间戳，**不用 Button 组件**（有点击延迟）；跟踪 touch id 防多点干扰。
- 对话：自动播放开关；暂停：顶部 72px 区域下拉或按钮，弹确认。
- 背包：不做手动拖拽，分类页签 + 一键排序。

### 短会话

- 进场即玩；切后台自动暂停 + 立即存档；防守中退出按"本波重打"处理；离线简报卡（图标化）。

### 盲区清单（真机前逐项检查）

- 异形屏安全区：关键交互距边缘 ≥ inset + 8px；横握遮挡左下 / 右下各 ~200px（右下不放需看清的信息）；
- 防误触：场景切换输入冷却；摇杆热区距边缘内收 24px；
- 像素字体 <20 设计 px 不可读——标题 / 数字用像素体，正文系统圆体 20-22px；
- 色弱形状冗余：成熟闪光描边 / 稀有星标 / 预警圈图案；
- 多点触控丢点保活；双槽滚动存档 + 关键节点落盘。

### 真机验证清单（14 条）

设备矩阵 3 台 / 交互可达率 ≥95% / 88px 首点准确率 ≥95% / 拖刷误触 <5% / 10 分钟战斗疲劳评分 ≤2 分 / 双拇指操作 100% 可达 / 钓鱼首日成功率 ≥90% / 装扮 8 件 ≤3 分钟 / 输入延迟 ≤100ms / 遮挡热区标注图 / 农场日常单手完成 / 色弱模拟通过 / 误触冲突排查 / 冷启动 ≤5s、重进 ≤3 步。

## 6. 关卡与地图规范

### 探险结构：手工房间链

- 5-7 房，单房 1-2 屏 / 30-45 秒；采集 / 战斗 / 宝箱房交替，禁同质连排；1-2 岔路。
- **五段节奏**：进入（0:00-0:20 安全房预告本图主题，不战斗）→ 探索（2-3 房，每房一个重点）→ 中点抉择（岔路 + 安全点，2:00-3:00——继续深入 vs 转撤回捷径，整次探险的核心决策点）→ 高潮房（精英怪 + 宝箱 / 封印碎片，3:00-4:30）→ 撤回（捷径直回 + 1-2 只追击怪制造"带战利品逃跑"张力，4:30-5:00）。
- 加载：入口叙事过场（推门 / 穿雾 + 一行地名题字）吞掉加载 + 后台预加载（验收：真机点入口到可操作 ≤2s 无白屏）；撤回后轻结算（收获逐条浮现），重结算并入农场日常；一次出门 = 一个完整会话。

### 三区分离：维持分场景

- 防守做"**农场战斗状态**"（复用农场地形，省一张图，"怪物闯进你家"空间叙事最顺）；农场边缘做"可见远方"剪影替代半开放农场；**场景管理留可替换接口**（为将来无缝化预留，返工成本关键）。

### 防守四环

- 预警期不完全情报 → 布置期受限决策（布置格有限 + 陷阱耗材料 + 防守作物占耕地 = 牺牲产量；允许免罚重摆）→ 职责克制波次（见 4.3）→ 按位置归因结算。

### 机制点子（灰盒先行）

- **封印潮汐门**：图内通道 / 桥被异界雾周期性淹没，雾退露出捷径与额外采集点（计时器 + tween + Collider 开关，低成本）；
- **诱饵农圃**：防线外廉价诱饵田，怪物 AI 优先扑食、进食停留数秒 = 可控延时闸门（进食状态扩展，低-中成本）；
- **单向落差**最先灰盒（单向 Collider 零成本）——若高度降级则随二期；
- 房间模块模板（门位 / 尺寸 / 敌人密度槽位）在内容扩展期前建立，避免手工房间成产能瓶颈。

## 7. 技术骨架与数据表

### 关键决策

- 时间基准 = dayIndex（见 4.5）；MVP 不启用物理引擎；防守状态机 PREP → WAVE → INTERMIT → RESULT；NodePool 池化怪物 / 投射物 / 飘字，同屏活跃实体 ≤60（中端机初值，须真机压测）；序列帧 + auto atlas，不用 Spine / 动态光照；纹理 point 采样保像素锐利（真机确认）。
- **设计分辨率注意**：技术评审骨架建议 1334×750，团队既定 1280×720——动工前统一（见 §10.4 附注），所有 UI 坐标随之固定。

### 第一周骨架（D1-D7）

- **D1-2** 工程配置（横屏、fitWidth、point 采样）；`launch` 场景（bootstrap + 载入进度）→ `farm` 场景；GameRoot 持久节点挂核心 manager。
- **D2-3** core 四基座：`core/EventBus.ts`（类型化发射器 ~50 行）/ `core/TimeSystem.ts`（dayIndex、endDay()、离线推进入口、时段 phase）/ `core/SaveManager.ts`（version + 迁移链 + 备份代 + 自动存档点注册）/ `core/DataManager.ts`（bundle 载入 + 注册表 + 引用完整性校验）。跨系统信号走 EventBus（dayAdvanced / itemGained / invasionWarning / weatherRolled），查询走 manager 单例直调；避免 `@property` 跨场景深引用。
- **D3-4** `app/GameApp.ts`（服务装配与启动顺序）；`platform/IPlatformAdapter.ts` + `LocalAdapter` + `taptap/TapAdapter` 空壳——落实 README 适配层原则，含平台评审要求的两个新增接口：**storage 适配接口**（分片 / flush / 信息查询）与**时间源接口**；onHide / onShow 生命周期由 GameApp 统一分发。
- **D4-5** `gameplay/farm` 垂直切片：FarmGrid / PlotView（种 → 浇 → 阶段推进 → 收）、虚拟摇杆 + 玩家移动、Interactable 最近目标交互、最小背包 `Record<itemId, count>`。
- **D5-7** `ui/`：HUD 骨架、Toast / 对话框工具、**DebugPanel（跳天 / 加物品 / 打印存档）——第一周就要**，后续每个系统的调试都吃它的红利。
- **周验收**：种地 → 浇水 → 连续结束数天 → 成熟 → 收获 → 杀进程重进存档完整还原；回拨系统时间无负生长、无免费离线推进；DebugPanel 跳天流畅。这一条链同时回答 §15"离线推进是否符合预期"原型问题。

### 数据表（assets/data 设为 Bundle "data"；catalogs = 静态实体定义，events = 日历 / 进度触发；全部字符串 id 互引，启动校验引用完整性）

- `catalogs/crops.json`：`id, name, seasons[], growDays, stages[{day, sprite}], waterNeed, harvest{itemId, min, max}, defense(null|{effect:'slow'|'attract', radiusCells, power}), sellPrice, rarity, codexId`

## 8. 平台红线与合规行动

### 包体

- 首包 ≤4MB（TapTap 与微信同值）、整包按微信口径 ≤30MB 规划（TapTap 上限 60MB，取严）；数值以提审时开发者后台为准。
- 首包预算 ≤3MB：引擎 + 代码 ~1.5MB + 农场图集 0.8-1MB + BGM 1 首（64kbps）~0.5MB + 关键短音效 ~0.5MB；**启动只进农场**，探险 / 防守 / 剩余音频全部分包；整包素材 ≤6MB。
- **中文 TTF 字库绝不内置**（几 MB）；正文系统字体，关键 UI 位图字体。
- tile 60-100 张 pngquant 8-bit；BGM 2-3 首 mp3 64-96kbps 单声道放分包（iOS ogg 兼容不稳，真机实测）；音效总量 ≤1MB。
- 节日主题包（§10）= 独立 bundle / 分包按需加载，防后期节日素材塞首包。
- 验收：首包 ≤4MB、整包 ≤30MB、真机冷启动 <5s；超限先砍引擎模块与图集冗余，不动玩法范围。

### 审核 / 资质【含立即行动】

- 无版号 + 无内购路线成立（publishing.md:9 已核对）；正式上架仍须前置备案 + 平台审核。
- ⚠️ **软著是唯一长周期前置**（个人登记普通流程约 1-3 个月）——**立即提交申请**，著作权人 = 开发者认证主体（或提供完整授权链），与开发并行。
- 前置备案材料：包体与实际内容一致、软著权属、游戏内容介绍说明（无版号必传，如实覆盖"轻度动作 / 塔防式防守"玩法）、负责人 = 本人、身份核验。材料归档 `release/taptap/compliance/`。
- 内容注意：怪物保持滑稽化避免血腥；不放充值 / 广告位残留；隐私如实写"数据仅存本地"。

### 待真机实测的推断项

- Tap storage 配额 / 清理行为（卸载重装、清缓存）；"转换为 Tap 小游戏"后的分包产物形态与后台上传方式（构建一次在插件面板实测，结果回写 publishing.md）；iOS 音频格式；最低适配机型性能基线（防守实体压测目标机）；横屏适配分辨率范围。

## 10. 分歧与拍板项（4 个决策）

> ✅ 拍板结果（2026-11-13）：四项均采纳推荐方案——①离线推进=方案 B（冷启动结算+上限）；②高度系统=首版平面+遮挡；③装扮=预布置展示；④素材=AI 生成+提示词表。game-design-draft.md 与 first-playable.md 已按 §11 修订至 v2。

### 10.1 离线推进规则【最重要分歧】

- **方案 A**（设计评审）：星露谷式——游戏日仅会话内推进，离线世界完全暂停；离线体验用信箱 / 信件补偿。优点：保住"日历-节气-入侵预告"节奏不被离线打乱、实现最简；风险：部分单机玩家预期"离线也在长"会落空。
- **方案 B**（平台 + 技术 + UX 评审，3/5）：冷启动结算离线时长，作物按整天粒度继续生长，上限 12-24 小时（超出按上限），作物只长不枯；防守绝不离线判定。优点：符合农场游戏玩家预期；风险：长期离线回来日历跳多天。
- **折中**（UX 评审方案）：作物离线只长不枯到可收获（24h 封顶），但 dayIndex / 日历 / 事件不推进——生长与世界解耦。
- 共识（任一方案下都成立）：挂后台 = 暂停；防守离线顺延；时间倒流按 0；上限封顶；规则游戏内明示；离线简报卡。
- 评审倾向：B 或折中（多数方支持"离线有生长"）；首轮试玩若反馈"想纯挂机"再回 A。

### 10.2 探险高度系统

- 建议：MVP 直接按平面 + 遮挡启动（两份评审判最高风险）；3 天 spike 作为**第二张图**的决策证据，不阻塞首版。
- 备选：先做 3 天 spike 再定首版——仅在"高台 / 楼梯"对你是不肯放弃的核心差异点时选。

### 10.3 房间装扮

- 建议：首版预布置房间展示，可编辑摆放二期（省 10-15 人日，不参与核心循环验证）。
- 备选：保留可编辑摆放进 MVP——仅在"自由布置"对你是核心体验时选，接受约 2-4 周额外工作量。

### 10.4 像素素材来源【A12，文档完全未覆盖】

- 选项 a：**AI 生成 + 提示词表**（16/32px 网格、中英双语提示词 + 负面词；团队已配提示词工程师）——风格一致性靠规范与批量重 roll 保障。
- 选项 b：购买像素素材包——最快，但多包风格拼接风险，需按基准尺寸筛选。
- 选项 c：自绘——风格最可控，产能风险最大（作物阶段 / 怪物动画 / NPC / 家具量级以千计）。
- 评审推荐：a 为主、b 补充通用 tile（与"直接生素材"的初衷一致）。
- **附注**：设计分辨率需统一——团队既定 1280×720 vs 技术评审骨架建议 1334×750，动工前定一个（建议维持 1280×720）。

### 10.5 存档实现备注（共识，无需拍板）

- 单一版本化 JSON + `.bak` 滚动备份 + 导出存档码进 MVP；分 key 分片仅在存档超 ~700KB 时启用（平台评审方案作为后备）。
