- **负责**: Level Designer（level-designer）
- **日期**: 2026-11-19
- **上游输入**: 协调者提供的 8 组主流调研（星露谷美术纪律 / theseus.fi 寻路论文 / 村庄分区方法论 / 星露谷 20 布局全景 / CSDN 双网格瓦片文 / Coral Island 分区 / Taming.io 留白 / gamedev SE 变体讨论）；本文将其转译为**本项目 24×11 屏口径下的可校验阈值**

## 结论先行

「干净」不是少做内容，而是**遵守 10 条可校验的密度纪律**。全部 10 条都可写成 `tools/validate-layout-*.py` 的自动检查（无需肉眼评审）。V2 违反其中 6 条（R1/R2/R3/R4/R6/R8 各有实锚），V3 几何以「全 10 条 PASS」为设计目标。

| # | 规则 | 本项目量化阈值（24×11 屏口径） | 来源 | V2 现状 | V3 落点 |
|---|------|------|------|---------|---------|
| R1 | **基底统治**：每屏有且只有一个统治性基底纹理 | 草地基底 ≥45%/窗（枢纽窗≥45%，野外窗≥55%）；基底必须是 grass | teemo.dev「大面积单一基底纹理」；theseus.fi「大片同质岛屿引导注意力」 | ✗ 出生窗仅 31%（诊断 E1） | 枢纽重排后 ≥50%（geometry §密度预算） |
| R2 | **每屏地面纹理上限** | 计入窗内 ≥12 格（≥4.5%）的纹理 ≤3 种；水/沙算「岸线单元」不计入种数但计入面积 | 9game/17173「元素不多但有特色」；Taming.io「不填满、一眼可读」 | ✗ 出生窗 4 种 | 全部 POI 窗 ≤3（geometry §六视角核验表） |
| R3 | **分区靠边界物，不靠换底** | 相邻功能区的分界必须有边界物（篱笆/树线/路沿/水深变化），两区底色相同时尤其必须；底色不同处允许硬边但需过渡策略 | eathealthy365「篱笆/树线/路沿定义分区」；teemo.dev「围栏/道具定义分区」 | ✗ 0 个边界物；pioneer∩living 重叠 7 格 | 篱笆+树线+河沿三类边界物（geometry §边界物表） |
| R4 | **路网层级与正交纪律** | 全图 1 主干（1 宽可通行即可）；每屏路开口 ≤2；同材质同宽同层；节点间距 ≥6 格；主干正交对齐（横平竖直），禁狗腿 | 星露谷布局全景「中规中矩/成排」；theseus.fi 相似律「统一资产→无噪音」 | ✗ 9 段同级 2 宽环网、出生窗 4 开口、pioneerV 狗腿 | 1 主干 + 4 支路，正交（geometry §路网表） |
| R5 | **变体不换色** | 同一底色用 2-4 档同色系微差变体打散重复感；变体≠新颜色 | gamedev SE「2-4 变体打散重复」；CSDN「同底多变体优于多种不同底」 | △ 6 底色 0 变体 | 草地 3 变体+石板 2 变体=**0 张新底图**（提示词侧工作） |
| R6 | **过渡瓦片预算** | 全图过渡瓦片种类 ≤6；只在「草地↔所有人工面」一个方向上做通用过渡，不做两两组合 | CSDN 47 张过渡瓦片失控教训 | ✗ 0 过渡（硬边） | ≤6 张通用边框（geometry §过渡策略） |
| R7 | **大区块分区** | 功能区 ≥1 屏（24×11=264 格）；相邻区之间 ≥2 格缓冲带（草地/河），白名单：河走廊、河→湖口 | Coral Island「大区块、屏幕级切换」 | ✗ advGate 仅 117 格、living/farm 零缓冲、pioneer∩living 重叠 | 全区 ≥1 屏 + 2 格缓冲（geometry §分区表） |
| R8 | **留白与物件密度** | 每窗：主建筑 ≤2、NPC ≤2、路牌 ≤1；功能区内部装饰密度 ≤10% 格位；允许成片无装饰草地 | Taming.io「不填满、留白」 | △ 出生窗 5 实体+UI，无预算约束 | 物件预算表 + 留白带（geometry §地标表） |
| R9 | **网格与剪影纪律** | 所有建筑/树/围栏锚点对齐 32px 网格（整格坐标）；每个地标有可辨识剪影；建筑朝向统一 | teemo.dev「16×16 纪律、剪影可读性、建筑对齐网格」 | △ 坐标已整格；剪影未审 | V3 坐标全整格 + 剪影提示词锁网格（素材侧对齐） |
| R10 | **地标轴线性与间距** | 关键地标（副本门/封印祭坛）压在主干/支路轴线上，沿轴走出即见；任意两个主地标的格距 ≥20 或有轴线关系 | 星露谷「建筑成排」；Lynch 路径/地标原则（通用） | △ 副本门在轴上✓、祭坛需二次转弯 | 副本门在 x=48 北轴、封印在西 defense 支路轴（geometry §地标表） |

## 证据位置
- 调研要点原文由协调者提供（teemo.dev / theseus.fi / eathealthy365 / 9game / 17173 / CSDN / gamerant / Taming.io / gamedev SE），本文未重新搜索；转译阈值由本文推导并标注推导口径。
- V2 违反项的量化证据全部见 `v3-clarity-diagnosis.md` E1-E5（坐标级账本）。
- 阈值推导口径：24×11=264 格/屏；「≥12 格才计入纹理种数」是为了排除窗缘 4-8 格的边缘侵入（否则任何相邻内容都会污染计数）——该口径在 R2/R8 两处一致使用。

## 风险条件
| 风险 | 位置 | 触发 | 影响 | 验证方法 |
|------|------|------|------|---------|
| R-B1 阈值是设计判断而非实证 | R1/R2/R8 数字 | 星露谷实际密度未被逐屏统计（调研为定性结论） | 阈值可能偏严/偏松 ±15% | 灰盒 A/B：45% vs 55% 基底两版出生屏各 3 人盲评 |
| R-B2 「水/沙不计种数」口径可争 | R2 | 若美术把湖做成品种繁多的水瓦片组合 | R2 失效 | 校验器只统计 land 类纹理集合 {grass,cobble,soil,forest,dirt}，水/沙单独走岸线检查 |
| R-B3 变体方案依赖素材侧 | R5/R6 | Image Prompt Engineer 产出的变体色相漂移超「同色系微差」 | R5 反向制造噪音 | 调色板锁定：变体仅允许明度 ±8%、色相不动（提示词文件约束） |
| R-B4 未验证项：10 条规则对「眼花缭乱」主诉的覆盖度 | 全表 | 用户主诉可能还包含动态元素（NPC 走动/特效） | 需补充动效密度规则（本文只管静态地面） | 灰盒用户测试后追加 R11（动效密度），超出本轮 |

## 可执行动作与验收标准
1. **A-B1**：10 条规则全部翻译为校验器检查项（优先级 R1/R2/R4/R7 四条先做，其余第二批）——验收：`validate-layout-v2.py` 跑 V2 几何至少 R1/R2/R4 三项 FAIL。
2. **A-B2**：规则表与 `docs/design/game-design-draft.md` §13 MVP 边界核对，确认无规则要求新增玩法系统（边界物=纯贴图+装饰格，非新机制）——验收：本文表内无「新增玩法」字样。
3. **A-B3**：R5/R6 的素材约束同步给 Image Prompt Engineer（变体=明度微差、过渡 ≤6 张）——验收：geometry 文 §过渡策略 与本文 R6 数字一致（≤6）。

## Handoff（交接协调者）
- **→ Image Prompt Engineer**：R5/R6/R9 的素材侧约束（同色系变体、≤6 过渡瓦、32px 网格锁定）需要落进提示词文件；本侧只定阈值，不产提示词。
- **→ Architect**：校验器扩展（A-B1）与「纹理集合统计」需要 TerrainData 基线数据结构里保留 ground-type 图层（见 geometry 文 §校验器增补）。
- **→ UI Designer**：R8 的物件预算不含 UI 层；UI 侧密度规则请在其产出中对齐同一「≥12 格才计数」口径。
- **未覆盖范围**：动态元素密度（R-B4）、音景对节奏的支撑（属音频成员）。
