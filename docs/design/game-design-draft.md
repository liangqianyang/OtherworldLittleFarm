# 异界小农场：游戏设计初稿

> 文档状态：v2 修订稿（2026-11-13）。已按 docs/design/design-improvement-proposal.md 的 5 份评审结论与 4 项拍板决策修订：①离线推进=冷启动结算整天+上限；②探险首版平面+遮挡；③装扮首版预布置展示；④素材=AI 生成+提示词表。数值仍需原型验证。

## 1. 项目概述

| 项目 | 方向 |
| --- | --- |
| 名称 | 异界小农场（暂定英文名：Otherworld Little Farm） |
| 类型 | 像素风单机农场经营、轻度动作探险、家园防守与收集 |
| 目标平台 | TapTap 小游戏，横屏优先 |
| 引擎 | Cocos Creator 3.8.x |
| 目标体验 | 轻松、温暖、有收获感；战斗有变化但不以高压操作为主 |
| 首版商业化 | 不接广告、不接内购；先验证核心玩法和平台运行 |

### 一句话介绍

玩家继承一座与异世界封印相连的旧农场。白天种植、钓鱼、布置居所并结识来访者；通过探险寻找修复农场和强化防守的材料；封印开启时，利用作物与设施抵挡怪物，逐步恢复农场并揭开异世界的来历。

## 2. 设计目标与体验支柱

### 2.1 经营带来稳定的日常

种植、浇水、收获、钓鱼和布置房间都应是低压力活动。玩家每次回到农场，都能完成一两件小事并看到可见变化。

### 2.2 探险服务于农场

战斗地图与农场地图是两个独立区域。探险不是另一套孤立刷图玩法，而是为农场带回种子、肥料、建材、装饰品和封印线索。

### 2.3 防守让准备变得有意义

封印入侵前的种植、设施摆放和材料准备会影响防守结果。成功防守带来稀有资源；失败造成可恢复的损失，不清空长期进度。

### 2.4 温和的长期收集

NPC、宠物、图鉴、房间套装、农场设施和封印剧情共同构成长期目标。限时内容采用游戏内日历和周期返场，避免现实时间错过后永久绝版。

## 3. 玩家与世界设定

玩家来到一座荒废但仍有人情味的旧农场。农场中央有一道被封印的异界通道，封印逐渐衰弱，通道另一侧的生物会被农场的作物和能量吸引。玩家需要一边恢复土地，一边探索周边遗迹、修复旧设施，理解当年封印的真相。

整体基调温暖、奇幻、略带神秘。怪物可以有奇特或滑稽的行为，避免把农场破坏表现得过于残酷；失败后的反馈强调“修整与重新规划”，而不是惩罚玩家。

## 4. 核心流程

### 4.1 一次常规游戏日

1. 回到农场查看天气、作物状态、NPC委托和封印预兆。
2. 浇水、种植、收获，整理背包或完成制作。
3. 选择钓鱼、室内布置、拜访NPC，或从探险入口出发收集材料。
4. 将探险收获用于升级农场设施、购买种子、制作防守道具或修复封印。
5. 夜间遇到预告中的防守事件，或结束当天并推进游戏内日历。
6. 领取成果、查看图鉴与剧情进度，安排下一天的计划。

时间主控：游戏以整数游戏日（dayIndex）为主时钟，在线由「结束一天」显式推进；不直接依赖真实时钟，离线结算规则见 §12。

### 4.2 核心循环

农场经营 → 选择活动 → 探险或钓鱼获取资源 → 制作、扩建和布置 → 准备防守 → 防守结算 → 解锁新作物、区域、NPC与剧情。

探险、钓鱼、种植和防守都可以作为一次游玩会话的主要内容，不强迫玩家每次必须完成所有活动。

## 5. 区域与地图结构

### 5.1 农场区

主基地和安全区，包含：

- 种植地：耕地、储物箱、种子台和灌溉设施。
- 水边：钓鱼点，后续可扩展鱼塘或不同水域。
- 住宅：卧室、客厅等可进入室内空间，用于家具摆放和NPC互动。
- 工坊：制作肥料、工具、陷阱、诱饵和修复材料。
- 封印入口：日常可查看状态；事件触发时切换至防守流程。
- 设施区域：温室、鱼塘、观景台等通过修复逐步开放。

### 5.2 探险区

经由农场入口进入，与农场分场景、分地图。每次探险选择一张路线或区域，在有限资源和生命状态下探索、战斗、采集，再决定继续深入还是撤回。

早期区域示例：

- 旧林地：基础木材、普通种子和初级肥料。
- 潮湿洞窟：矿物、特殊鱼饵材料和封印碎片。
- 失落温室：稀有种子、植物研究材料和剧情线索。

首版地图采用手工房间链：5-7 个房间，单房 1-2 屏（约 30-45 秒），采集/战斗/宝箱房交替编排，禁止同质连排；配 1-2 个岔路。单次探险按五段节奏展开：进入（安全房预告主题，0:00-0:20）→ 探索（2-3 房）→ 中点抉择（岔路+安全点，2:00-3:00，继续深入还是转撤回捷径）→ 高潮房（精英怪+宝箱/封印碎片）→ 撤回（捷径直回+少量追击怪制造张力）。地图不做成单一平面走廊。

固定图的重玩性依靠随机要素：采集点刷新表、宝箱位置种子、每日怪物配置变异与伪随机保底。

### 5.3 空间层次：首版平面 + 遮挡

拍板决策（2026-11-13）：首版探险地图为平面结构，用 2D 像素遮挡表达层次感；真实高台、楼梯、桥、单向落差移至二期，且第二张探险图启动前先做 3 天灰盒 spike（y-sort + 楼层 tag 原型），验证“高度关系能否一眼看懂”后再决定是否恢复。

首版执行的可读性规范：

- 脚底椭圆软阴影（透明度 25-35%）是“可行走平面”的唯一真值；无阴影 = 纯装饰不可交互。
- 前景遮挡物去饱和压暗 10-15%；角色进入遮挡物后方时遮挡淡出至 40-50% 透明；遮挡是否阻挡移动全图统一。
- 镜头整数像素、纯平移跟随，角色居中偏下；不做缩放。
- 够不着或不可交互的目标给出置灰/红叉否定反馈。

### 5.4 防守区

封印入侵发生时，玩法仍围绕农场，但切换至有明确战斗边界的防守场景或农场战斗状态。玩家可预先规划作物与设施位置，怪物从封印通道出现并尝试靠近农作物或封印核心。

## 6. 农场经营系统

### 6.1 作物

作物字段至少有种植季节、成熟时间、浇水需求、收获产物、用途和图鉴信息；数据结构保留品质字段，但品质/稀有度体系延后实装（MVP 不做分品质产出与 UI）。

- 普通作物：MVP 内全年可种（season 取 all），承担日常收入、食物和制作材料供给。
- 稀有作物：简化为“贵 + 慢”——售价与生长时间显著高于普通作物，不做独立稀有度体系。
- 防守型作物：MVP 只做减速与吸引两种效果（圆形光环每帧扫描）；阻挡与恢复延后。和普通经济作物之间保持占地取舍。

价格锚点（起点值，待调优）：普通作物售价 8 / 15 / 25，稀有作物 60；种子成本 ≈ 售价的 35%。货币只有 1 种（金币），经济闭环详见 §11.1。

肥料与加速道具主要通过探险、NPC委托、制作和防守奖励获得。首版避免大量付费加速设计。

### 6.2 节气与节日历

游戏有自己的日期推进方式，参考二十四节气和中外节日设计种植季节、装饰主题、商人商品、NPC委托和怪物外观/行为变化。

- 节气主要影响作物适种、天气、鱼类出没和环境表现。
- 节日主要影响活动任务、房间装饰、限定食谱、敌人主题和奖励。
- 特殊种子可在指定游戏内时段获得，也可通过对应探险或收藏兑换获得。
- 节日和限时种子按游戏内周期返场；错过一次不等于永久失去。
- 重大节日事件可以有独特规则，但不要求每个节日都制作全新地图和敌人。
- MVP 只查表实装 2-4 个节气/节日，验证「周期返场」规则；二十四节气与节日全量内容随后续版本补齐。日历与真实日期解耦是本作应对单机时钟问题的关键设计，保留不动。

### 6.3 钓鱼

玩家在农场水域进行短时、低压力的钓鱼小游戏。鱼类受水域、季节、天气、时段和鱼饵影响。鱼可以用于料理、NPC委托、图鉴、工坊材料或装饰展示。

首版目标是单个钓鱼点、单机制 QTE（收竿时机条：进度条 + 时机点击，难度由判定区宽与指针速度调节）和 3 种鱼；不做拉扯对抗条。交互采用全屏单点（咬钩窗口 ≥350ms、三重提示、失败零惩罚）。鱼塘与多水域作为扩展；天气只接两条规则——每日随机天气改变鱼池权重、雨天自动浇水。

## 7. 探险与战斗

### 7.1 探险目标

每次出发至少让玩家带回一种对农场有用的成果：材料、种子、肥料、加速道具、家具蓝图、鱼饵、遗迹碎片或剧情线索。战斗以清晰的移动、闪避和攻击为主，首版控制武器和怪物数量。

### 7.2 敌人与变化

基础敌人承担不同职责，例如追击型、远程型、护甲型和干扰作物型。节日变体优先复用基础行为，仅替换外观、弹幕或小规则，减少内容生产压力。

### 7.3 探险结算

玩家可在安全点撤回，保留已取得的部分收获；倒下或失败会损失部分未结算材料或消耗一次补给，不回滚已完成的剧情、设施修复和图鉴记录。具体损失规则需在原型中验证。

## 8. 封印防守与入侵事件

### 8.1 定时防守

防守节奏：每 4-6 个游戏日出现一次入侵预告；入侵强度随封印修复度上升。预告后的固定游戏内夜晚触发防守事件；波次为 2-3 波固定脚本（不做自由波次系统），怪物沿预设路径行进，不做自由寻路。

情报系统：每种怪物带口味标签（偏好/弱点/行为，如甜食虫扑向高甜作物、飞行种无视地面陷阱）；守门人在预告期给出不完全情报——本次怪物类型、进攻方向、弱点的模糊提示（如“怕火、爱啃庄稼”）。情报不完全使布置成为一种下注，不存在万能阵；两份不同情报应导向不同的最优布置。

波次编排（禁用“+20% 数量/+20% 血量”式难度递增）：

- 第 1 波·探测：单怪种小数量，让玩家看清路径与克制关系（兼教学）。
- 波间隔 60-90 秒：可修补、补种、有限次挪陷阱——波间动态调整权是策略感主体。
- 第 2-3 波·组合：按职责混合（护甲型顶前排 + 干扰型偷作物），逼玩家分兵。
- 终波·规则变化：入口偏移或新怪入场，奖励提前留后手者。

玩家可以提前：

- 选择种植哪些防守型作物，或保留普通作物产量。
- 在入口、道路和农田边缘布置陷阱或辅助设施。
- 制作诱饵、修复封印、准备恢复道具。
- 根据守门人情报调整作物选择与布置。

### 8.2 随机裂隙

在非预告时段也可能发生突发裂隙。随机裂隙已拍板延后至 MVP 之后：首版只保留预告型入侵（§8.1），避免两条触发链同时调参；后续若做，复用波次系统出“单波小规模入侵”，再评估完全突袭是否有趣。

### 8.3 胜负与损失

- 成功防守：获得封印碎片、稀有材料、种子或家具奖励；可提升农场安全度和剧情进度。
- 部分失守：MVP 按漏怪数量定损（按突破位置的归因展示随后补齐），少量作物被吃掉、踩坏或污染；部分设施需要材料修理。
- 防守失败：产生一段恢复任务或短期产量影响，不清空全部作物、不删除仓库、不重置长期解锁。

防守结果应让玩家理解损失原因，并能通过补种、修理和再准备恢复。避免让单次失败抹掉多日劳动。失败情绪层：首次失败免罚；连败软补偿采用“下次情报更详细”而非削弱怪物；恢复以修理清单 + 补种形式呈现，不建独立任务系统；结算提供归因面板（如“西侧无覆盖 → 3 株南瓜被吃”），战报本身就是教学——验收标准是失败后玩家不看日志能说出哪条路漏了。

## 9. NPC、宠物与剧情

NPC不是好友系统的替代联机，而是单机世界中可互动、可居住、可提供帮助的角色。完成各自任务后，角色可以搬入农场或开放服务。

| NPC | 主要功能 | 长期内容 |
| --- | --- | --- |
| 园艺师 | 作物知识、种子交换、温室指导 | 稀有作物与种植委托 |
| 钓鱼老人 | 钓鱼教程、鱼饵和鱼类线索 | 鱼类图鉴与水域传闻 |
| 守门人 | 解释封印预兆、协助防守准备 | 封印剧情与防守设施 |
| 旅行商人 | 周期性出售种子、家具或稀有材料 | 商品轮换和收藏目标 |

首版 NPC 不做任务框架：JSON 线性对话脚本 + 一次性触发 + flags/好感阈值条件。关系成长通过对话和农场变化表达，不设置必须每日上线的好感惩罚；个人支线与封印历史随后续版本展开。

农场宠物作为陪伴与轻功能系统：跟随、休息、发现少量采集物或提供情绪互动。首版可仅包含一只宠物与基础互动，不把关键战力锁在宠物培养后面。

### 长期目标

- 修复被封印的农场设施并开放新功能。
- 完成作物、鱼类、怪物和遗迹图鉴。
- 收集节日房间套装与家具蓝图。
- 帮助NPC定居并完成个人故事。
- 找到宠物、培养陪伴关系。
- 逐步揭开封印、异世界和旧农场的联系。

## 10. 房间装扮

卧室、客厅等室内空间的最终形态为格子吸附摆放：家具应有占地、旋转方向、交互类型和套装标签。

拍板决策（2026-11-13）：可编辑格子摆放移出 MVP（属编辑器级系统，约 10-15 人日，不参与核心循环验证）。首版提供 1 间预布置房间可参观，保住“温馨家园”视觉与商店页素材；二期实现可编辑摆放，届时注意：点选/拖动分离（位移阈值约 150px）、幽灵预览上偏 60-80px、支持撤销；像素家具旋转通常需美术单独绘制方向图，建议二期先只支持 0/180°。

装饰材料和家具蓝图来源：探险宝箱、封印防守奖励、钓鱼收集、NPC任务、旅行商人和节日活动。季节主题覆盖元旦/跨年、春节、端午、万圣节、圣诞节等；各地区节日内容作为可选主题包，核心剧情不依赖特定文化背景。

装扮不影响战斗平衡；少数家具可提供生活便利，例如储物、展示、休息或制作功能。二期从单间编辑扩展到多房间和主题套装；节日主题包按独立分包按需加载，不占首包。

## 11. 资源与奖励关系

资源设计围绕“活动带来不同类型的回报”，避免所有玩法只产出通用货币。

| 活动 | 主要产出 | 主要用途 |
| --- | --- | --- |
| 种植 | 作物、种子、料理材料 | 日常经济、制作、任务、防守选择 |
| 钓鱼 | 鱼、鱼类图鉴、装饰材料 | 料理、委托、收藏、家具 |
| 探险 | 建材、矿物、肥料、种子、蓝图 | 扩建、制作、解锁、升级 |
| 封印防守 | 封印碎片、稀有材料、特殊种子 | 修复封印、高级设施、剧情 |
| NPC任务 | 专属奖励、关系剧情、配方 | 解锁服务和长期目标 |

首版只需少量资源类别，并确保每种材料至少有一个明确用途。避免早期同时引入多套货币、复杂交易和重复合成链。

### 11.1 经济闭环（货币与出货）

- 货币只有 1 种：金币。
- 出货交互：收获物通过出货箱（或直接交付旅行商人/园艺师）换算金币；作物按 §6.1 价格锚点定价，鱼、材料和稀有品各有售价。
- 商店：种子购买走园艺师/旅行商人；价格锚点保证“普通作物日收益明显大于种子成本”的正反馈起点。
- 防守与探险奖励以材料、种子、封印碎片为主，金币为辅，避免通胀。
- 验收：4+1 作物每种一行——买价、卖价、成熟时长、日收益排序。

## 12. 单机、存档与商业化边界

- 首版是单机体验，不做好友拜访、赠送、协作探险或协作防守，不需要为这些功能建设联机后端。
- 存档优先本地保存，覆盖农场布局、日期、物品、作物状态、图鉴、NPC剧情和设置。存档工程约束（自第一天生效）：单一版本化 JSON 文档（带 version 字段 + 迁移函数链）+ 上一代滚动备份；只存 id/坐标/数值/时间戳，不序列化节点引用；落盘时机为结束一天、防守结算、切场景与切后台（onHide 强制 flush）；写失败时降级只保核心域；设置页提供存档风险说明与「导出存档码」（复制/粘贴恢复）。微信端单 key ≤1MB、总 10MB，MVP 存档预计 <100KB，超 ~700KB 再分 key 分片。
- 离线推进（拍板：方案 B）：挂后台 = 暂停游戏内时间；仅冷启动结算离线时长，按整天粒度推进作物生长，上限 12-24 小时，作物只长不枯；防守事件离线绝不判定失守，一律顺延到上线后的夜晚；时间倒流（now < 上次存档真实时间）按 0 处理；规则在游戏内帮助与离线简报卡中明示。核心逻辑不直接读系统时钟，统一经平台适配层时间源接口。
- 首版不接广告和内购。先验证核心玩法、留存体验和 TapTap 小游戏构建。
- 将平台能力放在可替换适配层（含 storage 适配接口与时间源接口；onHide/onShow 生命周期由应用层统一分发），后续若决定接入激励广告，再设计非必需奖励点；广告失败不能阻断主线或基础资源获得。

## 13. 首个可玩版本（MVP）

首版目标是验证“经营准备—探险收集—防守结算”的闭环，不追求铺开全部节日和地图。

### 必须包含

- 横屏像素风移动、交互和基础 UI（1280×720 设计分辨率；农场点击移动，热区 ≥88 设计 px）。
- 一张农场地图，包含耕地、水边、住宅、工坊和封印入口。
- 4种普通作物、1种稀有作物（贵+慢），支持播种、浇水、成长、收获和存档；农场操作含工具锁定、拖刷与一键收获。
- 一个钓鱼点、3种鱼和图鉴记录（首版图鉴只收作物+鱼，单表数据驱动）。
- 一间预布置可参观的室内空间（可编辑摆放延后）。
- 一张平面+遮挡的探险地图：手工房间链 5-7 房、采集点刷新、负重撤回简版、撤回/结算。
- 3种基础怪物（带口味标签）、基础移动与攻击、一场 2-3 波固定脚本的封印防守；守门人前夜情报简版。
- 两名功能NPC：园艺师和守门人（线性对话）。
- 金币经济闭环：出货交互 + 价格锚点（§6.1 / §11.1）。
- 一次防守成功奖励与一次部分失守恢复流程（按漏怪数量定损 + 归因面板原型）。
- 本地存档（version + 备份 + 导出存档码）、暂停、音量设置和 10 分钟任务链新手引导（种→收→钓→首波 1 怪防守）。
- TapTap 小游戏横屏构建与真机检查；平台验收：首包 ≤4MB、整包按微信口径 ≤30MB、真机冷启动 <5s；本阶段不接广告。
- 调试面板（跳天/加物品/打印存档）随首周骨架建立。

### 明确延后

- 多张探险地图、复杂随机地图生成和大型Boss。
- 多房间装修、家具套装收集全量内容。
- 全套二十四节气及多个国家的完整节日活动。
- 多名NPC个人长剧情与多宠物养成。
- 好友系统、云存档、联机协作和排行榜。
- 广告、内购、付费加速和运营活动后台。

## 14. 实施顺序

1. **项目可运行 + 空包真机**：建立主场景、横屏适配、输入、场景切换和本地存档骨架；同步完成 TapTap 空包真机构建，验证横屏无黑边、触控无偏移并记录包体基线（原第 6 步的平台风险提前到第一步暴露）。
2. **农场日常**：完成移动、交互、作物生长、背包、金币经济和调试面板。
3. **探险样板**：完成独立平面+遮挡地图（房间链 3-5 房）、一个战斗循环和负重撤回结算。（可选：3 天高度 spike，仅作第二张图决策证据，不阻塞主线。）
4. **防守闭环**：加入预告情报、2-3 波固定脚本怪物、设施/作物防守、归因结算和可恢复失败。
5. **生活内容**：接入钓鱼、预布置房间展示、NPC 线性对话和图鉴。
6. **平台验证**：完整构建 TapTap 包，在目标手机检查分辨率、触控、性能、音频、存档与广告未接入时的完整流程（含真机 14 条验证清单，见设计完善建议书 §5）。
7. **内容扩展**：根据试玩反馈增加地图、作物、节日、NPC和长期剧情。

## 15. 首轮原型需要回答的问题

- 横屏触控下，移动、攻击和农场交互是否舒适？（操作方案已定：农场点击移动、战斗动态摇杆，见 §17 触屏操作规范；原型验证舒适度）
- 多层地图的高度关系能否一眼看懂？玩家是否知道楼梯、平台和遮挡物的作用？（已转为二期 3 天 spike 决策项；首版平面+遮挡不依赖此问）
- 一次探险的时长和可携带战利品是否让人愿意再次出发？
- 防守前的准备是否有策略选择，而不是单纯堆数值？
- 失败损失是否让人紧张但不厌烦？
- 种植、钓鱼和装扮是否能在短会话中提供轻松收获感？
- 离线时间推进是否符合单机玩家预期？

## 16. 暂定设计原则

- 农场与探险使用独立地图，互相提供目标和资源。
- 首版不做永久错过的限时内容；节日奖励周期性返场。
- 防守失败不清空农场，损失有上限且可恢复。
- 所有核心进度都能通过正常游玩取得，不把关键内容绑定到广告。
- 优先做少量完整系统，再扩内容数量。
- 平台与广告 API 不进入核心玩法逻辑，便于后续调整发行方案。

## 17. 触屏操作规范

- 设计分辨率 1280×720，横屏；所有热区 ≥88 设计 px（≈44-48dp）；像素小按钮视觉/热区分离（视觉最小 64px + 透明命中区）。
- 农场：点击移动——点到交互物即交互、点到空地即移动，日常单手可完成；工具锁定 + 拖刷 + 一键收获，避免逐格操作的点击疲劳。
- 战斗：动态虚拟摇杆（左半屏任意按下生成原点）+ 攻击钮（直径约 120px，圆心约 (1150,560)）+ 闪避钮（96px，圆心约 (980,470)），距屏幕边缘 ≥24px；近战轻吸附、宽无敌帧、输入缓冲。
- 钓鱼：全屏单点交互；咬钩窗口 ≥350ms、三重提示（画面+震动+音效）、失败零惩罚。
- 短会话：进场即玩；切后台自动暂停并立即存档；防守中退出按“本波重打”处理；离线变化用图标化简报卡展示。
- 盲区检查：异形屏安全区（关键交互距边缘 ≥ inset+8px）、横握遮挡左下/右下各约 200px、场景切换输入冷却、正文像素字体不小于 20 设计 px（正文用系统圆体）、色弱用形状冗余（成熟闪光描边/稀有星标/预警圈图案）、多点触控丢点保活。
- 真机验证 14 条清单见 docs/design/design-improvement-proposal.md §5。

## 18. 资源与音频制作规范

- 像素素材：AI 生成 + 提示词表（拍板决策），tile 基准 16/32px 网格，中英双语提示词并附负面词；通用素材可辅以购买素材包。
- 图片：图集合并（auto atlas），pngquant 压 8-bit 调色板；纹理 point 采样保像素锐利。
- 字体：不内置中文 TTF 字库；正文用系统字体，标题/数字可用位图字体。
- 音频：BGM 2-3 首 mp3 64-96kbps 单声道，放分包；音效总量 ≤1MB；iOS 端音频格式需真机实测后统一。
- 包体：启动只进农场，探险/防守/剩余音频全部分包；首包预算 ≤3MB，整包素材 ≤6MB；节日主题包为独立 bundle 按需加载。

## 19. 发布与合规行动项

- 发行策略（2026-11-13 拍板）：先上 TapTap 小游戏验证效果，软著证书暂缓申请；前置备案「软件著作权人」以本人名义申报，若审核要求补充权属材料再补办软著（个人登记约 1-3 个月）。
- 前置备案：正式上架的硬性前置（工信部要求），与开发并行启动——全程约 20 个工作日，初审 12-16 个工作日后工信部短信核验，须 24 小时内完成否则退回。材料：与实际一致的包体、游戏内容介绍说明（无版号时必传）、负责人=个人主体本人、身份核验（扫码电子化）；流程细节归档 release/taptap/compliance/，操作笔记见 docs/taptap/publishing.md。
- 平台硬性约束：整包 ≤60MB（官方上限，本项目自设 30MB 执行）；当前暂不支持无网打开——启动需网络，本地存档与离线推进设计不受影响，但对外文案不承诺断网可玩；必接能力「添加到桌面」提审前接入。
- 服务端：单机无内购，首版不需要任何服务端（TapTap 登录/支付的服务端 API 均不涉及）。
- 内容红线：怪物保持滑稽化、避免血腥；不放充值/广告位残留；隐私说明如实写“数据仅存本地”。
- 待真机实测并回写 docs/taptap/publishing.md：Tap 端 storage 配额与清理行为、分包产物形态、iOS 音频格式、最低适配机型性能基线。
