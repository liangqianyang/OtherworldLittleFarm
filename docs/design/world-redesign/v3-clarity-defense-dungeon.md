1. **防守关**：8.1 的「预告→多波→结算」骨架已在 `defense_waves.json` 数据层成立（3 案全为固定编制、无数值递增、含情报与无泄漏奖励），**地表 V3 无需任何新战斗几何**；但存在 **2 个设计稿↔数据偏差**（预告周期 everyDays=12 vs 设计 4-6 日；波间隔 waveBreak=25s vs 设计 60-90s）必须由 Game Designer 拍板，以及 1 个失败流程（封印核心 HP 归零）未在数据中显式定义，交 Code Reviewer 做回归项。

## 2. 旧林地首版关卡：空间规格（按 5.3 平面+遮挡约束）

**通用规格**（每房）：
- 网格 24×13 格/房；外圈 1 格树墙环；可玩区 22×11；单屏容纳（视口 24×11，相机整数像素钳制、不缩放）。
- 门 = 树墙 2 格豁口 + 石板门垫 1×2（复用 cobble）。
- 地面纹理 ≤3 种/房（继承 R2）：基底 grass；主题房 forest 占比 ≤40%。
- 遮挡物：树丛 2×2 单元；遮挡瓦去饱和压暗 10-15%、角色入其后淡出 40-50%；**脚底椭圆阴影 = 可行走唯一真值**（5.3 原文约束）。
- 0 新素材：树/水/草/石板/土路全复用；「倒木」用树精灵横置（横置变体可选，非必需）。

### 2.5 实施形态
- **推荐：一房一场景 + 门传送**——与现有 adventure_rooms 房间链数据结构零冲突、无相机/无缝大图工程量；备选「单图纵排 7 房」二期再议。
- 搭建顺序：R0→R2 先灰盒（含 fork 假路验证）→ R4/R5 战斗房单独试玩调参 → R1/R3/R6 填充 → 全链串联。
- y-sort+遮挡淡出依赖 §5.3 已拍板的 3 天灰盒 spike（architect 排期），本布局对该 spike 无阻塞。

## 4. 可执行动作与验收标准
1. **A-X1**：本文布点表→Cocos 场景灰盒（7 房，纯色块+现有树瓦）——验收：房间链全通、两岔路可达、门位与表一致、单房 ≤1 屏。
2. **A-X2**：R4/R5 波次按 §2.2 触发线实现——验收：三波次触发条件逐一验证；TTD ≥15s（R-X5）。
3. **A-X3**：战利品表接线（复用现有 itemId）——验收：背包入账与表一致，无新 id 引入。
4. **A-X4**：防守侧仅两数字待拍板（everyDays / waveBreak）——验收：拍板结果回写 defense_waves.json 或设计稿 §8.1，二者必改其一且互相一致。
5. **A-X5**：失败流程补定义——验收：R-X2 回归用例通过。

## 5. Handoff（交接协调者）
- **→ Game Designer**（3 项拍板）：①预告周期 12 日 vs 4-6 日；②波间隔 25s vs 60-90s（本侧建议 45-60s）；③fork 时序偏差接受 or R1 增负；另探险首通 gold 20-30 为本侧建议价，需定价。
