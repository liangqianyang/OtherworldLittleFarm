# 大地图总体设计（World Redesign）

> 文档状态：v1（2026-11-16）。配套《game-design-draft.md》v2 与 2026-11-16 方向拍板：**一张连通大地图 + 可控角色**，整体结构借鉴星露谷、战斗借鉴元气骑士（副本内）、封印防守=大地图上的塔防区。
> 本文是大地图的**权威坐标来源**：2.1 区域矩形表、3.x 道路/桥/门坐标、7.x 给各专职位的接口约定，一经冻结不得随意改动（各区灰盒按此坐标拼装）。
> 适用约束：Cocos Creator 3.8.8 / 2D 斜俯视 3/4 视角 / 无物理引擎（手工 AABB+网格数学）/ TapTap 小游戏整包 ≤20MB / 微信容器 / 触屏优先。

## 0. 结论速览

| 议题 | 结论 |
| --- | --- |
| 地图尺寸 | **128×96 tile，tile 顶面 32px → 世界 4096×3072 px**；备选 96×72（过小）与 160×128（二期扩建方向，MVP 不做） |
| 视角/缩放 | 相机固定 **2×**（屏上 64px/tile，视口=世界 640×360=20×11.25 tile），全程纯平移不缩放（沿用 §5.3 拍板） |
| 布局 | 农场居中，居住区紧邻农场正北（出生点=家门口），开荒西北、探险东北角、防守正东、钓鱼正南；一条河从北贯南入湖作"世界脊线" |
| 连接 | 一棵"路树"（主干+3 支路）+ 2 座桥 + 6 个区域门（过门弹区域题字）；外圈 2 tile 树/岩环 + 远山剪影 |
| 加载 | **方案 A：单张 TiledMap 地面 + facade 数据驱动 16×16 chunk 激活**；唯一的真加载点=探险传送门（进副本），不做分区拼接 |
| 时间挂点 | 昼夜=全屏 tint overlay（按 `TimeSystem.phase` 色表）；季节=地砖 swap 表 + 草木 tint；存档 v2 增 `world` 段（增量） |
| 出生点 | tile (74,26)，居住区家门口；首屏含家、守门人、河岸、南向道路指引 |
| 增量成本 | 包体 <1MB（图集 ~300KB + world.json ~150KB）；GPU 纹理 +4MB；世界初始化 ≤400ms（中端机） |

## 1. 坐标系与尺寸

### 1.1 推荐尺寸与备选对比

**主常量：**

```ts
export const TILE = 32;                    // 顶面 32px；立面 sprite 底部 16-24px 压缩段（3/4 视角既定规范）
export const MAP_W = 128, MAP_H = 96;      // tile 数
export const WORLD_W = MAP_W * TILE;       // 4096
export const WORLD_H = MAP_H * TILE;       // 3072
export const ZOOM = 2;                     // 相机倍率（§3）
export const CHUNK = 16;                   // facade 激活 chunk 边长（tile）
```

| 档位 | tile 数 | 世界 px | 2×视口下屏数 | 全图对角步行(4.5 tile/s) | facade props 预算 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| 96×72 | 6,912 | 3072×2304 | ~31 屏 | ~22s | ~1000 | ❌ 过小：六区内部空间局促，居住区地形改造没地方施展，区间连接带比例 <25% → "六个孤岛"感反而更重 |
| **128×96** | 12,288 | 4096×3072 | ~54 屏 | ~36s | ≤1800 | ✅ **推荐**：区域内容积 ≈2.4× 星露谷标准农场（80×65），区间还能留 35% 连接带 |
| 160×128 | 20,480 | 5120×4096 | ~91 屏 | ~45s | ~3000 | 二期扩建方向（见 §2.6 预留），MVP 不做：内容产能翻倍、props +70%，首版风险大 |

"大但可控"的依据：**地图尺寸的成本大头不在 tile 数据，在 facade 节点数与美术量**。12,288 tile 的 gid 数据内存可忽略（见 1.3），128×96 的尺寸给六区 + 连接带刚好够用，且全图任意两点步行 ≤36s，日常循环（家→农场→钓鱼）单程 7-12s，不逼玩家做快速移动。

### 1.2 坐标换算（全项目统一）

地图网格 (col,row)，**row 0 = 正北**，与 Tiled 编辑器方向一致。世界坐标原点=地图节点左下角（Cocos 2D 常规，+y 向上）：

```ts
// tile → 世界中心点
export function tileCenter(c: number, r: number): Vec2 {
    return new Vec2(c * TILE + TILE / 2, (MAP_H - 1 - r) * TILE + TILE / 2);
}
// 世界 → tile
export function toCol(x: number): number { return Math.floor(x / TILE); }
export function toRow(y: number): number { return MAP_H - 1 - Math.floor(y / TILE); }
```

> 约定：所有设计文档、存档、区域矩形一律用 **tile (col,row)**；只有渲染层用世界 px。`col` 向东增大，`row` 向南增大。

### 1.3 内存 / 包体 / 耗时估算（128×96 依据）

| 项 | 估算 | 说明 |
| --- | --- | --- |
| 地面 gid 数据 | ~110KB 内存 | 4 层 × 12,288 tile × 2B（Uint16 gid 足够）+ 碰撞位图 12KB（Uint8/格） |
| 世界图集（GPU） | **4MB** | 单张 1024×1024 RGBA8888（≈1024 个 32px 槽位，够地面 autotile + facade 共用）；磁盘 pngquant 8-bit 约 250-400KB。**坚持 ≤1024²**：规避低端机 2048/4096 纹理上限与内存峰值 |
| facade props | 全图 ≤1800，同屏激活 ≤250 | 数据 `{pid,c,r}` ~40KB；激活节点 JS 堆 ~2MB |
| world.json（Tiled 导出） | 磁盘 80-150KB（构建期转 RLE） | 放主包直载（首包基线 811KB，余量充足） |
| **增量包体** | **<1MB** | 图集 + world.json + 季节地砖；整包素材既有预算 ≤6MB 不变，20MB 红线不受影响 |
| **世界初始化耗时** | **≤400ms**（中端机） | TiledMap 解析 ~150ms + chunk 索引 O(1800) ~5ms + 出生点周边激活 ~80ms（≤250 节点） |

### 2.3 布局逻辑（为什么这样摆）

1. **居住区放出生点、正邻农场**（用户最重视居住区）：家门 (74,26) → 农场北门 (74,42) 直线 16 tile ≈ **4 秒**。醒来到浇完第一块地之间没有无意义赶路；同时居住区在河北岸，玩家每天出门就看见自己改过的河——地形改造成果获得最高曝光。
2. **农场居中 = 路树根节点**：所有支路从农场出发，任何两区之间都"路过农场方向"，强化星露谷式的"以家为圆心"的世界感。
3. **防守区在农场正东、一条直路上**：入侵叙事最短——怪物从封印之门 (123,52) 沿预设路径向西，突破防守区西门就"踩进你家农田"（损失归因面板的位置叙事）。封印之门在地图最东缘=危险随距离递增的空间语言。
4. **探险区地表在东北角、被山脊与居住区隔开**：传送点是全图唯一"离开世界"的地方，放在角落远离生产区；地表只做遗迹门+传送点氛围（石柱/雾），副本在独立地图加载（元气骑士式，见 §7.4）。
5. **钓鱼区在正南、离封印最远**：安静水域不该和塔防区共享边界；湖面同时是全图南缘的视觉终点（对岸=远山剪影，呼应"可见远方"规范）。
6. **河流 = 世界脊线**：从北界 (64,0) 进入，纵穿居住区（**此段 (64±3, 2-35) 为可改造段**，默认河道），过农场与防守区之间的谷地（天然分界，省一圈围栏），东南入湖。水把六个区缝在一起。

### 2.5 "整体感"手法清单（防六个孤岛）

- **一条河串全场**（§2.3-6）：桥、码头、居住区改造段全部挂在这条河上。
- **一棵路树**（§2.4）：玩家闭着眼也知道"顺着主路走能回家"。
- **统一边界语法**：每个区域边界用同一种"自然屏障"语言（北=松林带、西=密林渐疏、东=河谷+山脊、南=湖岸），不用 UI 划线。
- **过渡带不空**：区与区之间 4-8 tile 的过渡带放低密度共享素材（野花/石头/树），禁止硬切 tile 色块；过渡带也承担"呼吸感"。
- **季节全图统一**（§5.2）：同一帧全图一个季节色板，是最大的整体感来源。
- **区域题字** + **题字色板沿用区域主题色**：进入区域 1.2s 横幅（已有触屏 UI 规范，无需新交互）。

### 2.6 二期扩建预留

- 南缘 (0,94)-(127,95) 与东缘 (126,0)-(127,69) 的边界环**只画不锁**：二期若扩到 160×128，向南/向东扩 32 tile，路树各接一个新门（南门→滩涂湿地、东门→深林）。MVP 阶段在 world.json 留 `reservedGates` 注释即可，不写代码。

## 3. 相机策略

### 3.1 参数（冻结）

```ts
export const CAM = {
    zoom: 2,                       // 固定 2×，全场景不缩放（§5.3 拍板：纯平移）
    followOffsetY: 48,             // 世界px：目标点在角色上方 → 角色画在屏中下方 ~96px（居中偏下规范）
    dampRate: 6,                   // 指数平滑系数 /s（~0.35s 收敛；太快晃、太慢拖）
    regionBanner: true,            // 过门题字代替任何镜头演出
};
```

### 3.2 跟随与像素对齐（伪代码）

```ts
// 每帧
const target = player.pos.add(0, CAM.followOffsetY);
cam.center = damp(cam.center, target, CAM.dampRate, dt);
// 点采样纹理防抖：对齐到屏幕整数像素（2× 下= 0.5 世界px）
cam.center.x = Math.round(cam.center.x * ZOOM) / ZOOM;
cam.center.y = Math.round(cam.center.y * ZOOM) / ZOOM;
// 边界 clamp：半窗按真实可视尺寸算（异形屏/fitWidth 下视口不是恒 640×360）
const hw = visibleWorldWidth() / 2, hh = visibleWorldHeight() / 2;
cam.center.x = clamp(cam.center.x, hw, WORLD_W - hw);
cam.center.y = clamp(cam.center.y, hh, WORLD_H - hh);
```

- **不做死区盒**：damp 跟随已足够稳；若试玩反馈"走路晃"，再加备选死区盒 **176×128 世界px**（2.75×2 tile）——先简后繁。
- **区域过渡不缩放**：唯一允许的"镜头事件"是过门题字与防守日开场（防守区是否临时 clamp 视口到竞技场，由防守专职位定，默认不）。
- 屏幕震动：预留给防守命中反馈（幅度 ≤4 屏幕px、≤0.2s），P1。

### 3.3 为什么是 2×（备选对比）

| 倍率 | 屏上 tile | 视口（tile） | 32px 角色屏高(6in 手机) | 评价 |
| --- | --- | --- | --- | --- |
| 1× | 32px | 40×22.5 | ~3.7mm | ❌ 角色太小，触屏情境按钮目标难辨；地图显"小气" |
| **2×** | **64px** | **20×11.25** | **~7.4mm** | ✅ 与 88px 热区/120px 战斗钮的触屏体系匹配；20 tile 视野对 48 tile 宽的农场比例合适 |
| 3× | 96px | 13.3×7.5 | ~11mm | ❌ 视野太窄，区域显小，赶路感变重 |

> 若试玩觉得"世界太小"，正确动作是**加内容（支路/ secret 点）而不是降倍率**；若觉得"太挤"，先调 followOffsetY 与 SPEED，不动 ZOOM。

## 4. 加载方案

### 4.1 对比

| | 方案 A：单张大图（推荐） | 方案 B：分区拼接 + 边界动态加载 |
| --- | --- | --- |
| 结构 | 1 个 TiledMap（地面 3 层+碰撞位图）+ facade 数据表驱动 chunk 激活 | 6 个子 TiledMap/bundle，跨区边界做重叠缝合 |
| 实现量 | ~3-4 人日（chunk 管理器 + y-sort 容器） | ~8-10 人日 + 边界缝合调试 |
| 加载体验 | 冷启动一次成型，全程无加载点 | 每次跨区 60-150ms 卡顿或过场 ×6 边界——直接违背"无缝大地图"的立项初衷 |
| 内存 | 全量 gid 110KB（可忽略）；激活窗口外 facade 不占节点 | 略省 GPU/节点（只在 2-3 区），但图集若共享则差距 <10% |
| 存档/改造 | 一个 world 段，居住区改造跨边界无障碍 | 跨区状态拆 6 份，改造/砍伐状态合并逻辑复杂 |
| 适用规模 | ≤3 万 tile 都舒服 | >5 万 tile、或有独立大子世界（地下城/室内）才值得 |

**结论：MVP 用方案 A。** 12,288 tile 远低于方案 A 的舒适上限；方案 B 留给"二期扩到 160×128+"或"居住区室内可进入空间"的场景。**全图唯一真加载点 = 探险传送门**（进副本独立地图，沿用"入口叙事过场吞加载"的既有规范：点传送门 ≤2s 无白屏）。

### 4.2 chunk 激活机制（facade 层）

地面走引擎 TiledMap（自带分块渲染与视口剔除，无需自管）；**facade（树/屋/石/篱笆/桥面等一切需要 y-sort 的立绘）**数据驱动激活：

```ts
// world_props.json: [{pid:'tree_oak_01', c:17, r:31}, ...]  构建期按 chunk 分桶
const ACTIVE_MARGIN = 16;      // tile：激活窗口 = 相机窗 + 16 tile
const DEACT_MARGIN  = 32;      // tile：退出窗口（滞回防抖动）
const DEACT_DELAY_S = 0.5;     // 离窗 0.5s 后才回收进 NodePool

每帧：算 visibleChunkSet（≈4×3=12 chunks，含 margin）
  → 激活：instantiate from pool，挂 y-sort 容器（layer 一致——别踩 pitfalls#1）
  → 回收：out of DEACT_MARGIN 且超时 → pool 回收
预算：同屏激活节点 ≤250；单 chunk props ≤60；全图 ≤1800
```

- y-sort：facade 容器优先用引擎 2D Y-Sort（3.8 节点级开关），**灰盒首日必须验证**；兜底=每帧对激活节点按 y 增量排序 + `setSiblingIndex`（≤250 节点 <0.3ms）。y 锚=立面底边（即所在 tile 顶面南缘）。
- 遮挡淡出沿用 §5.3 既有规范：角色被 facade 挡住时该 sprite 淡至 40-50%。
- 视觉规则配套：**任意 facade 总高 ≤2 tile（64px）**，保证 16 tile 激活窗足够、遮挡塔不超过 2 层。
- 合批：facade 与地面共用同一张 1024 图集 + 同材质 → CC 3.x 2D 相邻同纹理自动合批；DC 预算 ≤40（真机验收项）。

### 4.3 启动时间线（沿用冷启动 ≤5s 验收）

```
launch（bootstrap+进度条）
 ├─ 并行：bundle 'data'（10 表 + world_props.json） ∥ 'texture'（世界图集并入）
 ├─ 挂 TiledMap(world.json)           ~150ms
 ├─ 建 facade chunk 索引（O(n) 分桶）  ~5ms
 ├─ 激活出生点周边 chunks（≤250 节点） ~80ms
 ├─ player/NPC/情境按钮系统就位
 └─ 'worldReady' → 淡入（世界段合计 ≤400ms 中端机目标）
```

## 5. 与 dayIndex 时间系统的挂点

TimeSystem（dayIndex 主时钟、14 天/季、`DayPhase` morning/day/evening/night、56 天/年）保持纯逻辑不动；世界层只**读**状态 + 监听事件。现状盘点：`phase` 目前只在 endDay/reset 时置 Morning，**日内无推进驱动**（见 §8 开放问题 #1）。

### 5.1 昼夜视觉（tint overlay）

- 实现：UI 层最末端一个全屏节点（1280×720，layer=UI_2D，显式继承父层——pitfalls#1），`Graphics` 填色，**普通 alpha 混合**（像素风格下"色罩"观感成立，1 个 DC，不引自定义 shader/光照）。
- 色表（起点值，待真机调）：

| phase | 色值 | alpha | 附带 |
| --- | --- | --- | --- |
| morning | #FFE9C4 | 36/255 | 暖晨 |
| day | — | 0 | 无罩 |
| evening | #FF9C48 | 66/255 | 暮色 |
| night | #26346E | 112/255 | 夜 + 家窗灯换发光帧 + 门口灯笼亮（同一图集 2 帧，swap 即可） |

- 切换：监听 `phaseChanged`（新增事件），overlay 色/alpha tween 0.8s。
- 防守联动：入侵夜由防守流程 `TimeSystem.setPhase(Night)`（新增公开方法+emit），世界随之入夜——防守氛围免费获得。

### 5.2 季节地表（低成本三板斧）

1. **地砖 swap 表**（新美术仅 2 张）：`'dayAdvanced'` → `TimeSystem.inst.season` 变化 → emit `seasonChanged` → 对 ground 层按表换 gid：草春/夏=`ground_grass`、秋=`ground_grass_autumn`、冬=`ground_snow`（TiledLayer 逐格 `updateTileAt` 或整层重建，~2000-3000 格 <20ms，一次性）。
2. **草木 tint 零新美术**：激活中的 foliage 类 facade 设 `sprite.color`：春/夏=白、秋=#E8A03C、冬=#B9C6D4；chunk 激活时按当前季节上色（ activation 成本≈0）。树落叶换帧（冬树 2 张）P1。
3. **作物/图鉴不动**：crops.json 的 seasons 逻辑（现有 `cropInSeason`）照旧；冬雪地+绿苗的违和感见 §8 开放问题 #4。

### 5.3 天气（沿用既有两条规则）

`weatherRolled` 雨天：overlay 叠加 #5A6C88 α60 + 雨滴粒子（P1）+ 既有"雨天自动浇水"逻辑不变。

### 5.4 存档挂点（SaveDataV2 增量段）

```jsonc
"world": {
  "ver": 1,
  "player": { "x": 2384, "y": 2224 },        // 世界px；缺省回出生点
  "chopped": [1021, 1023],                    // 已砍伐/清走 prop 的 pid（>500 棵时转位图/RLE）
  "terraform": [{ "c": 66, "r": 20, "g": 817 }],  // 居住区地形改造增量（仅限居住区矩形，越界拒绝写入）
  "built": [{ "pid": "bridge_s", "c": 66, "r": 20 }]
}
```

- 迁移链 v1→v2：`if (!s.world) s.world = { ver: 1 }`（字段只增不删，符合既有存档工程约束）。
- 落盘时机沿用：结束一天 / 防守结算 / **切场景（进探险副本即触发）** / onHide flush。
- 离线结算跨季：冷启动直接以目标 season 初建世界（swap 表+tint 一次到位），不做过渡动画。

## 6. 移动、碰撞与交互（与既有触屏规范对接）

```ts
export const SPEED = 144;          // 世界px/s = 4.5 tile/s（星露谷步行量级）；冲刺 6 tile/s P2
// 摇杆：动态虚拟摇杆（左半屏），max 半径 96 屏幕px，deadzone 8%，幅度→速度线性
```

- **碰撞**（手工 AABB，无物理引擎惯例）：玩家脚底 AABB 22×14 世界px；移动分轴（先 x 后 y）resolve vs ①碰撞位图（solid gid：水/树环/岩壁/屋体）②facade 底座矩形（树干 16×12、箱体全 footprint）。水面不可走（钓鱼区交互靠"走近"判定：目标水 tile 与玩家曼哈顿距离 ≤2 tile 即可情境交互）。
- **情境交互按钮**：最近可交互物半径 2 tile（64 世界px）内 → 按钮浮现于其上方（UI 层换算），热区 ≥88px——全部沿用 §17 触屏规范；战斗钮 (1150,560) 只在副本/防守态出现。
- **步行时间预算**（4.5 tile/s，验收用）：家→农场中心 7s / 家→开荒腹地 10s / 家→栈桥 12s / 家→防守西门 8s / 家→传送点 9s / 全图对角 36s。任一日常"出门成本"≤12s，超出即调 SPEED 或补捷径，**不改地图尺寸**。

## 7. 分期接入路线与各专职位接口（冻结物）

### 7.1 冻结物（各区灰盒拼装的公共依赖）

- §1 坐标系与常量、§2.1 区域矩形表、§2.4 路桥门坐标、河脊线默认河道。
- EventBus 新增事件：`phaseChanged` / `seasonChanged` / `regionEntered{regionId}` / `worldReady`。
- `WorldView` 容器接口：`attachProps(regionId, propList)`（各区把自己的 facade 表注册进来）、`setSolid(c,r)`、`worldToTile / tileToWorld` 工具。

### 7.2 接入顺序

| 期 | 内容 | 依赖 |
| --- | --- | --- |
| P0 骨架 | 128×96 灰盒 world.json + chunk 管理器 + 相机 + 出生点/家 + 主干路 + y-sort/遮挡灰盒验证（首日 spike） | 无 |
| P0+ | 农场区搬迁：3×3 地块（见 §7.3）+ 出货箱 + 存档 world 段 | P0 |
| P1 | 开荒区（砍树/采石落地 + chopped 存档）→ 钓鱼区（栈桥交互） | P0+ |
| P1 | 防守区挂点（§7.5）+ 探险传送门（§7.4） | P0+ |
| P2 | 居住区地形改造全量（河流改道/台阶/地窖，专人设计）+ 季节美术 + 夜灯/粒子 | P0+ |

### 7.3 农场搬迁（FarmSystem 不动，视图重写）

- FarmSystem/EconomySystem 纯逻辑单例零改动；FarmGrid/PlotView 从 CELL=150 的 UI 画布重写为世界节点。
- 3×3 地块：每块 footprint **2×2 tile（64×64px）**，块间距 1 tile，起点 tile **(48,46)** → 占 (48,46)-(55,50)；围栏包边；出货箱 (72,72)（南门内侧）。
- 迁移后回归既有验收链：种→浇→收→跳天→杀进程还原。

### 7.4 探险挂点（元气骑士式副本）

- 传送点 tile **(114,14)**（遗迹门 facade 4×3 tile 居 (112,12)-(117,16)）；走近交互 → 入口过场（推门/穿雾+题字，吞加载）→ 加载现有 adventure 副本地图（独立场景/bundle，房间链五段节奏规范照旧）。
- 撤回/结算 → 返回世界，落点 (114,17)（传送点南侧 3 tile）；负重战利品入包走既有结算。
- 副本内世界观不与大地图共享相机（副本自有战斗相机/摇杆规范）。

### 7.5 防守区挂点（塔防，另有专人）

WorldView 只提供场地，波次/情报/结算全在 DefenseSystem：

```jsonc
// world.json → defenseHook
{ "arenaRect": [96,34,125,69],
  "spawnGate": [123,52],                  // 封印之门=怪物出生点
  "pathWaypoints": [[123,52],[110,54],[96,55],[87,55]],   // 预设路径，不做寻路（既有拍板）
  "farmGate": [87,55],                    // 突破点=损失归因的地理锚
  "westGate": [96,55] }
```

- 非入侵日：防守区可自由走动预览（布置模式仅预告期开放，规则归防守专人）。
- 入侵日：建议入口管制 + 相机 clamp 到 arenaRect（可选，默认只提示），夜 tint 由 setPhase(Night) 驱动。

### 7.6 居住区挂点（地形改造，另有专人）

- 改造合法域=居住区矩形 (60,2)-(99,35)；默认河道 (64±3, 2-35) 可改道，改道增量走 `terraform` 存档段。
- 改造对世界层的要求只有三条：①改完刷新 ground 层 gid + 碰撞位图（提供 `setSolid`）；②新 facade 走 attachProps；③河/台阶的 y-sort 与遮挡淡出沿用全图规范。其余玩法内部设计不受本文约束。

## 8. 风险与开放式问题

### 风险（按优先级）

| # | 风险 | 缓解 |
| --- | --- | --- |
| R1 | 引擎 2D Y-Sort 行为与遮挡淡出叠加的排序异常（透明 sprite 深度） | **P0 首日灰盒 spike**（y-sort+淡出+chunk 回收三合一验证）；兜底手动 sibling 方案已写入 §4.2 |
| R2 | TiledLayer 运行时改 gid（季节 swap、居住区改造）的 API/性能差异（3.8.8） | 0.5 天 spike：批量 `updateTileAt` 3000 格实测；不行则整层重建或自管地面 mesh |
| R3 | 低端机 GPU 内存峰值（世界图集 4MB+UI/角色/NPC 图集叠加） | 全项目 GPU 纹理预算 ≤20MB；复用空包真机流程早测；图集坚持 ≤1024² |
| R4 | AI 素材六区风格漂移（调色板不一致 → 孤岛感复发） | 每 region 一条锁定 palette 的提示词 + 生成后色板校验脚本（gen_pixel_art 管线加检查） |
| R5 | 农场 CELL=150→32px 网格迁移回归 | 逻辑层不动只重写视图；迁移后跑种浇收+存档验收链 |
| R6 | 128×96 试玩偏大（钓鱼/探险出门意愿低） | 先调 SPEED 160-180 或 P2 快捷移动（路牌传送）；尺寸表冻结不动 |
| R7 | 微信首包：world.json+图集入主包的体积余量 | 现首包 811KB，余量足；若紧张把世界图集移分包预载（'texture' bundle 已是按需加载） |
| R8 | props 手摆产能（1800 个） | 程序化散布（森林泊松采样+排除路/水）为主，关键点位手摆；chunk 索引构建脚本化 |
| R9 | 相机 0.5px 对齐在部分机型仍有 shimmer | 真机清单加一项；必要时对齐粒度放宽 1 世界px |
| R10 | facade 高度失守（有人画 3 tile 高立面）遮挡层级崩 | §4.2 立面 ≤2 tile 写入美术规范与提示词负面表 |

### 开放式问题（需拍板/与专人确认）

| # | 问题 | 建议默认值 |
| --- | --- | --- |
| Q1 | **日内 phase 推进驱动**（现状：phase 只在 endDay 时置 Morning，日内永不变）——会话时长推进（如 Morning 0-6min/Day/Evening/18min+Night，session 内计时）？还是活动驱动/手动？影响钓鱼时段条件与昼夜观感 | GameApp 内加 `DayPacingPolicy`（不动 TimeSystem 核心），MVP 用会话时长档；试玩嫌"被时钟赶"再改手动 |
| Q2 | 进副本期间世界态（暂停/离线规则是否适用） | 副本=同一次会话，世界暂停；副本失败/撤回不推 dayIndex |
| Q3 | 防守日玩家在非防守区是否受罚（漏怪即损 vs 强制传送） | 漏怪即损（空间自由保留，归因面板教学），不做强制传送——归防守专人终审 |
| Q4 | 冬季可种性：crops 全季可种 + 雪地绿苗违和 | MVP 保持现状（all 季可种，雪=纯地表色），二期给冬作物/覆膜视觉 |
| Q5 | 快捷移动（路牌传送/坐骑/冲刺）排期 | P2；先看 12s 出门成本试玩数据 |
| Q6 | 小地图/世界地图页 | P1 建议做：地面 TiledMap 缩略静态图 256×192 + 玩家点 + 区域名，成本极低、治愈迷路 |
| Q7 | 居住区改河与钓鱼区湖水是否联动水位 | MVP 仅视觉不联动；玩法联动（上游改道→下游鱼种）列 P2 观察项 |
| Q8 | 地面编辑器选型：Tiled（推荐，半天学习）vs 自研 JSON 网格工具 | Tiled 导出 JSON 进 assets/maps/world/；props 单独 JSON 进 'data' bundle |
| Q9 | chopped 列表超 500 条后的存档体积 | 转 Uint8 位图（1800 props=225B）；存档 <100KB 红线内无忧 |
| Q10 | 探险副本地图与"地表探险区"边界：副本是否要分主题（林地/洞窟/温室对应三个地表氛围点） | 二期；MVP 一张副本图 + 传送点单一入口 |
